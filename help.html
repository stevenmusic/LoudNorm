它是怎麼運作的

能用純增益解決的，就絕不做動態處理。先量測整段音訊，算出需要多少 dB， 確認這個增益不會讓峰值超標，然後就只做「乘上一個固定數字」這一件事——數學上完全透明， 音色、動態、立體聲相位、瞬態全部原封不動，只是變大聲。

只有在峰值真的不夠用的時候（例如素材裡有爆音、拍打聲），才會啟用真實峰值限幅器， 而且只用在「差的那幾 dB」，成品做完後會再重新量一次確認真的達標。

流程

  1. 量測依 ITU-R BS.1770 / EBU R128 量測整合響度與真實峰值。
  2. 決定算出需要幾 dB。峰值餘裕夠就純增益結束；不夠才動用限幅。
  3. 輸出並驗證影像串流直接複製，音訊套用增益後編碼。做完立刻重新量測成品， 如果峰值還是超標會自動修正增益、重跑一次——這個保證來自實測的數字，不是假設安全邊際一定夠。

畫質完全不變

影像軌是直接複製，從頭到尾沒有解碼、沒有重新編碼。可以自己驗證：來源與成品的影像串流 MD5 完全相同。

ffmpeg -i 原始.mp4 -map 0:v -c copy -f md5 -
ffmpeg -i 成品.mp4 -map 0:v -c copy -f md5 -

為什麼峰值上限是 -1 dBTP，而不是 0

數位訊號的取樣點之間還有波形。播放器把它還原成類比、或平台把它轉成 AAC/Opus 時， 還原出來的波形峰值會比原本的取樣點更高。留 1 dB 餘裕，就是為了讓這個「還原後的超出量」 不至於在觀眾的裝置上削波。這是所有串流平台交件規範的共同做法。

常見問題

處理完還是比別人的影片小聲？

如果出現「比目標小聲」的提示，代表素材裡有少數非常大聲的瞬間（爆麥、拍桌、碰撞聲）， 把整體音量「頂住」了。回去剪掉／修掉那幾個突波是最好的做法——限幅器能做的事有限， 再多聲音會明顯變扁。

為什麼影片輸出是 AAC？這不是有損嗎？

是。改變音量必然要重新編碼音訊，這一步無法避免。瀏覽器版統一輸出 AAC／Opus， 實務上聽不出差異。

純音訊檔案為什麼輸出的是 WAV？

WAV 是無損格式，瀏覽器版對音訊檔一律輸出 24-bit 無損 WAV（並套用三角形高通 dither， 避免降低位元深度時產生的量化雜訊），確保「不改變音質」這個承諾百分之百成立。

可以順便降噪嗎？

可以，就緒畫面上有一個「降噪比較（選用）」的勾選框，預設不開。開啟後會同時處理 「原始」與「降噪」兩個版本，完成畫面上可以切換 A/B 聽過再決定要下載哪一個——降噪 只會做保守處理（自動偵測噪音層級、降噪幅度也刻意壓低），適合底噪、電流聲、風聲這類 穩定的雜訊，很吵或很不規則的雜訊沒辦法完全去除。因為要處理兩次，時間會比平常長一些。 如果是影片檔，降噪版在切換比較時只會有聲音、沒有畫面（避免同時把兩份完整影片留在 手機記憶體裡），選定要下載那個版本時才會補上畫面，下載按鈕會短暫顯示「產生完整 影片中」。

可以自己輸入目標響度嗎？

可以。平台選單選「自訂目標…」，就能自行輸入整合響度（LUFS）與真實峰值上限（dBTP）， 運作方式和選預設平台完全相同，一樣是先量測、算出增益，不夠才動用限幅。

5.1 環繞聲道的影片也能處理嗎？

可以。量測時會依 ITU-R BS.1770 對環繞聲道正確加權（不是只看前左右兩聲道）， 聲道數與空間定位也會完整保留，處理前後只有整體音量不同。

可以匯出處理紀錄嗎？

處理完成後可以下載一份 JSON 格式的響度報告，記錄處理前後的 LUFS／真實峰值、使用的目標、 是否動用限幅等資訊，方便存檔或交給後製團隊核對。

怎麼知道素材裡響度有沒有忽大忽小？

完成畫面可以展開「顯示響度曲線」，看整段素材處理前後的響度隨時間變化， 方便確認有沒有某幾段特別大聲或特別小聲。

檔案不會被上傳到哪裡吧？

不會。整個處理過程用的是 WebAssembly 版的 ffmpeg，直接在你的瀏覽器裡執行， 檔案從頭到尾只存在你的裝置記憶體裡，沒有任何網路上傳。這也是為什麼瀏覽器分頁關掉、 處理就會中斷——沒有伺服器在背景繼續幫你跑。

影片很大或很長，處理很慢或分頁當掉怎麼辦？

瀏覽器版沒有硬性大小限制，但影片會整個載入記憶體處理，沒有串流機制， 裝置效能與可用記憶體是實際上限。建議短片（幾分鐘、幾百 MB 內）用瀏覽器版就好； 建議先用較短的片段測試看看。

我的影片格式顯示不支援怎麼辦？

目前支援 H.264／HEVC（輸出 MP4）與 VP8／VP9／AV1（輸出 WebM）的影片， 涵蓋絕大多數手機錄影與網路影片。遇到其他格式，建議先用其他工具轉成 MP4 或 WebM 再上傳。
