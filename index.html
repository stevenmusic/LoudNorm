EBU R128 · ITU-R BS.1770

把影片音量調到剛剛好

自動提升到 YouTube 標準響度。不破音、不改變畫質，輸出可以直接上傳的成品。

開始使用 完整說明 
$ ./loudnorm 我的影片.mp4

✓ 完成：我的影片_loudnorm.mp4
   目標   -14.00 LUFS    -1.00 dBTP   （YouTube）
   原始   -28.43 LUFS   -12.10 dBTP
   成品   -14.02 LUFS    -1.20 dBTP
   處理  提升 14.41 dB（純增益，不改變音質）
   影像  h264 1920x1080 原封不動複製（未重新編碼）

左右滑動可看完整輸出

能用純增益解決的，就絕不做動態處理。

只有峰值真的不夠用時才啟用真實峰值限幅器，而且只用在差的那幾 dB。

實測數據

不是設計目標，是開發時實際跑出來的數字。

誤差 < 0.05 dB
-1.2dBTP 峰值
穩守上限內
0.000ms 影音位移
限幅已補償
MD5影像串流
位元完全相同

三個「不改變」

每一項都可以自己驗證。

畫質完全不變

影像軌直接複製，從頭到尾沒有解碼、沒有重新編碼。來源與成品的影像串流 MD5 完全相同。

不做動態處理

全程 64-bit 浮點。輸出 .mkv／.mov 時音訊存成無損，等於原始訊號乘上一個固定增益。

不破音

峰值以 4 倍超取樣的真實峰值為準，而不是取樣點峰值。成品會再量一次確認沒有超標。

怎麼運作

跟母帶工程師一樣的流程。

  1. 量測依 EBU R128 量測整支片的響度與真實峰值。有加配樂就量混完之後的結果。
  2. 決定算出需要幾 dB。峰值餘裕夠就純增益結束；不夠才動用限幅，並回頭試算修正。
  3. 輸出並驗收一次編碼完成，影像直接複製。最後重新量測成品，把實際數字報給你。

開始使用

只需要 ffmpeg 和 Python，不必安裝任何 Python 套件。

1. 安裝 ffmpeg

# macOS
brew install ffmpeg

# Windows
winget install Gyan.FFmpeg

# Ubuntu / Debian
sudo apt install ffmpeg

2. 執行

# 圖形介面（或雙擊 launcher）
python3 -m loudmaster --gui

# 指令列
./loudnorm 影片.mp4

# 輸出無損音訊
./loudnorm 影片.mp4 -o 成品.mkv
