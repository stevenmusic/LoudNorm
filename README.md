# LoudMaster

把影片的音量提升到 YouTube 等平台的標準響度——**不破音、不改變畫質、盡可能不改變音質**。
不用安裝任何東西，直接在瀏覽器裡用。

**[直接開啟工具 →](https://stevenmusic.github.io/LoudNorm/)**

拖進影片或音樂檔，選平台，按「開始處理」，下載成品。全程在瀏覽器裡用 WebAssembly 版的
ffmpeg 處理，檔案不會上傳到任何伺服器。適合幾分鐘、幾百 MB 內的短片。完整說明、平台列表、
常見問題見 [help.html](https://stevenmusic.github.io/LoudNorm/help.html)。

```
✓ 完成：我的影片_loudnorm.mp4
   目標   -14.00 LUFS    -1.00 dBTP   （YouTube）
   原始   -28.43 LUFS   -12.10 dBTP
   成品   -14.02 LUFS    -1.20 dBTP
   處理  提升 14.41 dB（純增益，不改變音質）
   影像  h264 1920x1080 原封不動複製（未重新編碼）
```

---

## 這個工具在做什麼

上傳到 YouTube 的影片如果太小聲，觀眾要一直調音量；如果太大聲，YouTube 會自己把它轉小，
而且**不會**因為你的影片小聲就幫你轉大。所以「剛剛好」是有一個明確數字的：
**-14 LUFS**（整合響度），且真實峰值不超過 **-1 dBTP**。

LoudMaster 的做法刻意跟大多數「自動聲音加大」工具不同：

> **能用純增益解決的，就絕不做動態處理。**

它會先量測整支片子，算出需要多少 dB，確認這個增益不會讓峰值超標，然後就只做「乘上一個
固定數字」這一件事。這在數學上是完全透明的——音色、動態、立體聲相位、瞬態全部原封不動，
只是變大聲。

只有在**峰值真的不夠用**的時候（例如素材裡有爆音、拍打聲），才會啟用真實峰值限幅器，
而且只用在「差的那幾 dB」，成品做完後會再重新量一次確認真的達標。

## 三個「不改變」，分別是什麼意思

| 項目 | 保證程度 | 說明 |
|---|---|---|
| **畫質** | **完全不變（位元完全相同）** | 影像軌直接複製，從頭到尾沒有解碼、沒有重新編碼。可以自己驗證：來源與成品的影像串流 MD5 是一樣的。 |
| **音質** | **不做動態處理** | 等於「原始訊號 × 一個固定增益」。純音訊輸出是無損 WAV；影片輸出因為容器限制，音訊會重新編碼成 AAC／Opus，但不會經過任何動態壓縮。 |
| **不破音** | **有量測保證** | 全程 64-bit 浮點運算；峰值以 4 倍超取樣的「真實峰值」為準，成品做完後會重新量測、必要時自動修正，確認沒有超過上限。 |

## 隱私

整個處理過程用 WebAssembly 版的 ffmpeg，直接在你的瀏覽器裡執行。檔案從頭到尾只存在你的
裝置記憶體裡，沒有任何網路上傳。

## 支援的格式

* 影片：H.264／HEVC 輸出 MP4；VP8／VP9／AV1 輸出 WebM。涵蓋絕大多數手機錄影與網路影片。
* 音訊：WAV／MP3／FLAC／M4A 等常見格式，輸出為無損 WAV。

## 限制

瀏覽器版沒有安裝限制，但整部影片會載入記憶體處理，沒有串流機制，所以裝置效能與可用記憶體
是實際上限。適合短片（幾分鐘、幾百 MB 內）；長片或大檔案建議先用較短的片段測試。

## 開發

原始碼結構、測試方式、以及技術細節（為什麼峰值上限是 -1 dBTP、為什麼限幅器要用
`latency=1` 補償等）見 [help.html](https://stevenmusic.github.io/LoudNorm/help.html)。

```
index.html          網頁工具本身
help.html           完整說明、平台列表、常見問題
vendor/ffmpeg/      同源封裝的 ffmpeg.wasm（不依賴外部 CDN）
loudmaster/         Python 核心邏輯（響度量測、增益／限幅決策、ffmpeg 濾鏡圖）
```

網頁版的響度母帶邏輯是從 `loudmaster/mastering.py` 移植過去的同一套決策規則，兩邊的核心
概念相通：先量測、算出需要的增益，峰值不夠才動用限幅器。
